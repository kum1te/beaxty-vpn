# Автоматическое переключение VPN-сервера

*Описание экспериментальной функции. Она выключена по умолчанию.*

## Что делает функция

Если активный VPN-маршрут перестаёт отвечать, приложение пробует подключиться к резервному серверу из списка, который заранее выбрал пользователь. Это помогает восстановить доступ к интернету без ручного выбора узла.

Смена сервера меняет внешний IP-адрес. Игровые сессии, звонки и другие активные соединения могут оборваться; функция восстанавливает VPN-доступ, но не сохраняет текущие сессии.

## Как происходит переключение

1. Пользователь включает функцию, выбирает резервные серверы и задаёт порядок выбора.
2. Пока приложение показывает состояние «Защищено», оно примерно раз в 3 секунды проверяет активный маршрут небольшим HTTP-запросом через VPN. Проверяются настроенный адрес проверки и резервные публичные адреса; успешного ответа хотя бы от одного достаточно.
3. После первой неудачи приложение повторяет проверку примерно через 0,8 секунды. Одиночный сбой не запускает переключение.
4. Если обе проверки не проходят, приложение по очереди запускает выбранные резервные серверы. Порядок определяется последним известным пингом либо последовательностью в списке.
5. После запуска каждого узла приложение проверяет маршрут через него. Если проверка не проходит, узел останавливается и приложение пробует следующий.
6. После успешной проверки приложение показывает фактически используемый резервный сервер. Выбранный пользователем основной сервер остаётся сохранённым, автоматического возврата на него нет.
7. Если весь пул исчерпан, приложение сообщает об ошибке и повторяет попытку через 30 секунд. После следующих неудач пауза растёт до 5 минут. Ручное подключение отменяет отложенную попытку.

## Выбор резервов

- **По последнему пингу:** сначала пробуются узлы с меньшей последней измеренной задержкой. Если пинг неизвестен, узел остаётся в конце списка; при равных значениях сохраняется порядок добавления.
- **По порядку:** узлы пробуются в том порядке, в котором пользователь добавил их в пул.

Случайный выбор не используется: порядок остаётся понятным и повторяемым.

## Время и нагрузка

Проверка запускается раз в 3 секунды и использует активное ядро и уже выбранный маршрут. В нормальном случае обычно достаточно одного короткого HTTP-запроса. При неисправности проверяются дополнительные адреса, затем нужен повторный цикл подтверждения.

Обнаружение сбоя может занять до примерно 9–10 секунд с учётом ожидания очередной проверки и таймаутов. Затем добавляется время запуска резервного узла и его проверки. Оно зависит от сети, сервера и системы; точного верхнего предела для запуска ядра пока нет.

## Ограничения и безопасность

- Проверка определяет доступность HTTP-маршрута через VPN, а не работоспособность каждого сайта, игры или протокола. Если все адреса проверки недоступны из конкретной сети, возможна лишняя попытка переключения.
- Если у пользователя пропал интернет, резервные серверы тоже не пройдут проверку. Приложение будет повторять попытки с растущими паузами.
- При переключении старый туннель останавливается перед запуском нового. Между ними защита туннеля прерывается, и часть трафика может пойти через обычную сеть. Текущий Kill Switch приложения не гарантирует системную блокировку. Поэтому функция остаётся выключенной по умолчанию, а её включение сопровождается предупреждением.
- При сбое ядра ситуация может быть хуже: без отдельного системного firewall приложение не гарантирует блокировку трафика после аварийного завершения процесса.

До выпуска нужно проверить работу на реальных серверах и операционных системах, включая время разрыва туннеля и поведение системного трафика. Тесты интерфейса не заменяют проверку реального подключения.
